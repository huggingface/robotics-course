# LeRobotDataset

LeRobotDataset — это стандартизированный формат набора данных, разработанный для решения конкретных потребностей исследований обучения роботов. В следующие несколько минут вы увидите, какие проблемы он решает, как он организован и где искать в первую очередь при загрузке данных.

Формат обеспечивает унифицированный, удобный доступ к данным робототехники по модальностям, включая сенсомоторные показания, множественные потоки камер и статус телеуправления. LeRobotDataset также хранит общую информацию о собираемых данных, включая текстовые описания задач, тип используемого робота и специфику измерений, такую как кадры в секунду для потоков изображений и состояния робота, вместе с типами используемых камер, их разрешением и частотой кадров.

> [!TIP]
> **Почему специализированный формат?** Традиционные наборы данных ML (например, ImageNet) просты: одно изображение, одна метка. Данные робототехники намного сложнее:
> - **Многомодальные**: Изображения + показания датчиков + действия, все синхронизированы
> - **Временные**: И наблюдения, и действия записываются во времени и очень последовательно
> - **Эпизодические**: Данные организованы в траектории/эпизоды
> - **Высокоразмерные**: Множественные виды камер (т.е. множественные изображения), состояния суставов, силы и т.д.
>
> LeRobotDataset бесшовно обрабатывает всю эту сложность!

LeRobotDataset предоставляет унифицированный интерфейс для обработки многомодальных данных временных рядов и бесшовно интегрируется с экосистемами PyTorch и Hugging Face.

Он расширяемый и настраиваемый, и уже поддерживает открыто доступные данные для различных воплощений в LeRobot, от платформ манипуляторов, таких как SO‑100 и ALOHA‑2, до гуманоидных рук и кистей, наборов данных на основе симуляции и даже автономного вождения.

Формат построен для эффективности обучения и достаточно гибкий, чтобы приспособиться к различным типам данных, при этом способствуя воспроизводимости и простоте использования.

## Дизайн класса набора данных

Вы можете прочитать больше о дизайнерских решениях, лежащих в основе дизайна нашего класса набора данных [здесь](https://huggingface.co/blog/lerobot-datasets-v3).
Основное дизайнерское решение, лежащее в основе LeRobotDataset, — это разделение базового хранилища данных от пользовательского API. Это позволяет эффективное хранение, представляя данные в интуитивном, готовом к использованию формате.

Думайте об этом как о двух слоях: компактная компоновка на диске для скорости и масштаба, и чистый интерфейс Python, который выдает готовые к обучению тензоры.

Наборы данных всегда организованы в три основных компонента:

- **Табличные данные**: Низкоразмерные данные высокой частоты, такие как состояния суставов и действия, хранятся в эффективных файлах с отображением памяти и обычно выгружаются в более зрелую библиотеку `datasets` от Hugging Face, обеспечивая быстрый доступ с ограниченным потреблением памяти.
- **Визуальные данные**: Для обработки больших объемов данных камер кадры объединяются и кодируются в файлы MP4. Кадры из одного и того же эпизода всегда группируются вместе в одно и то же видео, а несколько видео группируются по камере. Чтобы снизить нагрузку на файловую систему, группы видео для одного и того же вида камеры также разбиваются на несколько подкаталогов.
- **Метаданные**: Коллекция JSON-файлов, которая описывает структуру набора данных с точки зрения его метаданных, служащая реляционным аналогом как табличным, так и визуальным измерениям данных. Метаданные включают различные схемы признаков, частоты кадров, статистику нормализации и границы эпизодов.

Когда вы просматриваете набор данных на диске, держите в уме эти три категории — они объясняют почти все, что вы увидите.


Для масштабируемости и поддержки наборов данных с потенциально миллионами траекторий (что приводит к сотням миллионов или миллиардам отдельных кадров камеры) мы объединяем данные из разных эпизодов в одну и ту же высокоуровневую структуру.

Конкретно, один файл данных (хранящийся в файле parquet) или запись (хранящаяся в формате MP4) часто содержит несколько эпизодов. Это ограничивает количество файлов и ускоряет ввод-вывод. Компромисс заключается в том, что метаданные становятся "картой", которая говорит вам, где начинается и заканчивается каждый эпизод. В свою очередь, метаданные имеют гораздо более "реляционную" функцию, аналогичную тому, как в реляционной базе данных общие ключи позволяют извлекать информацию из нескольких таблиц.

Пример структуры для данного LeRobotDataset будет выглядеть следующим образом:

- `meta/info.json`: Эти метаданные являются центральным файлом метаданных. Он содержит полную схему набора данных, определяя все признаки (например, `observation.state`, `action`), их формы и типы данных. Он также хранит важную информацию, такую как кадры в секунду набора данных (`fps`), версию LeRobot на момент захвата и шаблоны путей, используемые для поиска файлов данных и видео.
- `meta/stats.json`: Этот файл хранит агрегированную статистику (среднее, стандартное отклонение, мин, макс) для каждого признака по всему набору данных, используемую для нормализации данных для большинства моделей политики и доступную внешне через `dataset.meta.stats`.
- `meta/tasks.jsonl`: Этот файл содержит отображение из описаний задач на естественном языке в целочисленные индексы задач, которые полезны для обучения политики с условием задачи.
- `meta/episodes/*`: Этот каталог содержит метаданные о каждом отдельном эпизоде, такие как его длина, соответствующая задача и указатели на то, где его данные хранятся в файлах набора данных. Для масштабируемости эта информация хранится в файлах, а не в одном большом JSON-файле.
- `data/*`: Содержит основные табличные данные по кадрам, используя файлы parquet для быстрого доступа с отображением памяти. Для повышения производительности и обработки больших наборов данных данные из нескольких эпизодов объединяются в более крупные файлы. Эти файлы организованы в фрагментированные подкаталоги, чтобы размер каталогов оставался управляемым. Один файл обычно содержит данные для более чем одного эпизода.
- `videos/*`: Содержит файлы видео MP4 для всех потоков визуальных наблюдений. Аналогично каталогу `data/`, видеоматериалы из нескольких эпизодов объединяются в отдельные файлы MP4. Эта стратегия значительно сокращает количество файлов в наборе данных, что более эффективно для современных файловых систем.

Руководство по чтению: начните с `meta/info.json`, чтобы понять схему и fps; затем проверьте `meta/stats.json` для нормализации; наконец, загляните в один файл в `data/` и `videos/`, чтобы соединить точки.

> [!TIP]
> **Эффективность хранения:** Объединяя эпизоды в более крупные файлы, LeRobotDataset избегает "проблемы маленьких файлов", которая может замедлить файловые системы. Набор данных с 1M эпизодов может иметь только сотни фактических файлов на диске!
>
> **Профессиональный совет:** Файлы метаданных действуют как индекс базы данных, позволяя быстро получать доступ к конкретным эпизодам без загрузки целых видеофайлов.
