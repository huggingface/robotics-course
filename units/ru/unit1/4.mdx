# Пример кода: Наборы данных на практике

В этом разделе показано, как работать с наборами данных робототехники из Hugging Face с использованием класса LeRobotDataset. Мы начнем с простых примеров и постепенно добавим сложность, чтобы вы могли скопировать и адаптировать подход, который лучше всего подходит для вашего проекта.

Ключевая вещь для понимания — это то, что любой набор данных в Hub, который следует формату LeRobot (с табличными данными, визуальными данными и метаданными), может быть загружен всего одной строкой кода.

При работе с данными робототехники часто нужно смотреть на несколько временных шагов одновременно, а не на отдельные точки данных. Почему? Большинству алгоритмов обучения роботов нужно видеть, как вещи меняются со временем. Например, чтобы поднять объект, роботу может потребоваться увидеть, что произошло в последние несколько моментов, чтобы лучше понять текущую ситуацию. Аналогично, многие алгоритмы работают лучше, когда они могут планировать несколько действий вперед, а не просто решать, что делать прямо сейчас.

LeRobotDataset упрощает это с помощью "временного окна". Вы просто объявляете, какие временные смещения вы хотите (т.е. текущий кадр плюс два предыдущих), и он автоматически обрабатывает сложность получения этих кадров, даже когда некоторые могут отсутствовать в начале или конце эпизода.

![streaming-multiple-frames](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobotdataset-v3/streaming-multiple-frames.png)

> [!TIP]
> **Объяснение временных окон:** 
> - **История наблюдений**: `[-0.2, -0.1, 0.0]` дает вам наблюдения за 200 мс, 100 мс и текущие
> - **Последовательности действий**: `[0.0, 0.1, 0.2]` предоставляет текущее и следующие 2 действия (с интервалом 100 мс)
> - **Автоматическое заполнение**: Отсутствующие кадры на границах эпизодов обрабатываются автоматически. Набор данных всегда возвращает запрошенное количество кадров и применяет заполнение там, где необходимо.
> - **Маска включена**: Знайте, какие кадры реальные, а какие заполнены для правильного обучения

Удобно, что используя LeRobotDataset с PyTorch `DataLoader`, можно автоматически объединять отдельные словари образцов из набора данных в один словарь пакетных тензоров для последующего обучения или вывода. LeRobotDataset также нативно поддерживает режим потоковой передачи для наборов данных. Пользователи могут передавать данные большого набора данных, размещенного на Hugging Face Hub, с изменением одной строки в их реализации. Потоковые наборы данных поддерживают высокопроизводительную пакетную обработку (около 80-100 итераций/с, варьируется в зависимости от подключения) и высокий уровень рандомизации кадров, ключевые функции для практических алгоритмов BC, которые в противном случае могут быть медленными или работать на сильно не i.i.d. данных. Эта функция разработана для улучшения доступности, чтобы большие наборы данных могли обрабатываться пользователями без необходимости в больших объемах памяти и хранилища.

Вот различные способы настройки временных окон в зависимости от вашего случая использования. Просмотрите варианты и выберите один для начала — переключение позже — это просто изменение словаря.

**Базовое поведенческое клонирование** (изучение текущего действия из текущего наблюдения):

```python
# Просто: текущее наблюдение → текущее действие
delta_timestamps = {
    "observation.images.up": [0.0],  # Только текущий кадр
    "action": [0.0]  # Только текущее действие
}

dataset = LeRobotDataset(
    "lerobot/svla_so101_pickplace", 
    delta_timestamps=delta_timestamps
)
```

**BC на основе истории** (использование истории наблюдений для лучших решений):

```python
# Использование истории наблюдений для контекста
delta_timestamps = {
    "observation.images.up": [-0.2, -0.1, 0.0],  # История 200 мс
    "action": [0.0]  # Текущее действие
}

dataset = LeRobotDataset(
    "lerobot/svla_so101_pickplace",

)

```

```python
delta_timestamps = {

dataset = LeRobotDataset(

    delta_timestamps=delta_timestamps
)

# Форма изображений: [2, C, H, W] - 2 кадра наблюдения
# Форма действия: [4, action_dim] - 4 предсказания действий
```

### Потоковая передача больших наборов данных

> [!TIP]
> **Когда использовать потоковую передачу:**
> - **Набор данных > доступное хранилище** - Передавайте наборы данных, которые не помещаются на ваш диск
> - **Экспериментирование** - Быстро пробуйте разные наборы данных без загрузки
> - **Облачное обучение** - Сократите время запуска, передавая данные из Hugging Face Hub
> - **Сеть доступна** - Требуется стабильное интернет-соединение во время обучения
>
> **Производительность:** Потоковая передача достигает 80-100 итераций/с при хорошем подключении! Это (в среднем) сопоставимо с локально хранимыми наборами данных, исключая накладные расходы на инициализацию.

<hfoptions id="dataset-loading">
<hfoption id="download">

**Загрузить набор данных** (быстрее обучение, требуется хранилище):

```python
from lerobot.datasets.lerobot_dataset import LeRobotDataset

# Загружает набор данных в локальный кэш
dataset = LeRobotDataset("lerobot/svla_so101_pickplace")

# Самый быстрый доступ после загрузки
sample = dataset[100]
```

</hfoption>

**Потоковый набор данных** (хранилище не требуется, требуется интернет):

```python
from lerobot.datasets.streaming_dataset import StreamingLeRobotDataset

# Передача данных без загрузки
streaming_dataset = StreamingLeRobotDataset(
    "lerobot/svla_so101_pickplace",
    delta_timestamps=delta_timestamps
)

# Работает точно так же, как обычный набор данных
sample = streaming_dataset[100]
```

## Интеграция обучения

Вы можете легко интегрировать обычные и потоковые наборы данных с загрузчиками данных torch. Это делает интеграцию любого LeRobotDataset с вашим собственным циклом обучения (`torch`) довольно удобной. Поскольку мы извлекаем все кадры из наборов данных как тензор, обертывание итерации по набору данных с обучением особенно просто.  

### PyTorch DataLoader
Вы можете легко интегрировать обычные и потоковые наборы данных с загрузчиками данных torch. Это делает интеграцию любого LeRobotDataset с вашим собственным циклом обучения (`torch`) довольно удобной. Поскольку мы извлекаем все кадры из наборов данных как тензор, обертывание итерации по набору данных с обучением особенно просто.
```python
import torch
from torch.utils.data import DataLoader
# Создать DataLoader для обучения
dataloader = DataLoader(
    dataset,
    batch_size=16,
    shuffle=True,
    num_workers=4
)

# Цикл обучения
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

for batch in dataloader:
    # Переместить на устройство
    observations = batch["observation.state"].to(device)
    actions = batch["action"].to(device)
    images = batch["observation.images.up"].to(device)

    # loss = model(observations, images, actions)
    # loss.backward()
    # optimizer.step()
```
## Почему это важно

Этот простой API скрывает значительную сложность:
- ✅ **Многомодальная синхронизация** - Изображения и датчики идеально выровнены
- ✅ **Эффективное хранение** - Сжатые видео, массивы с отображением памяти
- ✅ **Временная обработка** - Легкий доступ к последовательностям наблюдений/действий  
- ✅ **Масштабируемость** - Тот же код работает для маленьких и массивных наборов данных

Сравните это с традиционной обработкой данных робототехники, которая часто требует:
- Пользовательские парсеры для каждого формата данных
- Ручную синхронизацию по модальностям
- Сложную буферизацию для временных окон
- Платформо-специфичный код загрузки

LeRobotDataset **стандартизирует и упрощает** все это!
